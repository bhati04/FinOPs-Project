# Reports, notifications, and audit

Milestone 7 provides tenant-scoped CSV and PDF reports for executive summaries,
daily cost detail, and recommendation review. Reports are generated by the
Celery worker, never in the API request, and remain private to the organization
that requested them.

## Generation and storage

- On-demand requests accept an optional AWS connection and an inclusive period
  of at most 366 days.
- CSV cells sourced from customer data are protected against spreadsheet
  formula execution.
- PDF output is a compact dependency-free summary; CSV remains the complete
  detail format.
- Local development uses a private report volume. Production configuration
  rejects local storage and requires a private S3 bucket.
- Stored objects have a SHA-256 checksum, byte count, content type, and
  expiration timestamp. The hourly expiration task deletes the object and
  retains expired metadata for history.

## Scheduling and notifications

Daily, weekly, and monthly schedules are stored in PostgreSQL. A separate
Celery beat scheduler checks due definitions every five minutes and queues
normal report jobs. Schedule rows are locked with skip-locked behavior so
concurrent schedulers cannot claim the same row.

Email is disabled by default. When the SES provider is configured, the
platform execution role sends a short report-ready notice. Reports are never
attached to email; recipients authenticate to CloudWise before downloading.
Every delivery attempt is recorded as sent, failed, or skipped. Recipient
addresses and message content are never logged.

## Append-only audit trail

Every authenticated POST, PUT, PATCH, or DELETE request produces one
organization-scoped audit event after authorization. Events contain the actor
UUID, normalized route action, entity family, outcome, HTTP status, correlation
UUID, and UTC timestamp. They do not contain credentials, authorization
headers, cookies, environment values, request bodies, AWS external IDs, or
report contents.

Owners and administrators can view up to 500 recent events through the audit
interface. PostgreSQL rejects UPDATE and DELETE statements on the audit table
with a trigger, enforcing append-only behavior below the application layer.
